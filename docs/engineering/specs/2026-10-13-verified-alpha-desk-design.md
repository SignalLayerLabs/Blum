# Verified Alpha Desk

The user asks for development and release of the improvements we judge necessary to pursue a financial research platform superior to Bloomberg and a leading alpha caller. They explicitly chose both equities/ETFs and Forex, evaluated separately. Success in this release means verifiable prospective calls and honest comparable evidence; it does not mean an unsupported claim of superiority to proprietary products. Implementation and publication are delegated by the user. Work uses the existing task-owned clone and native execution, with independent review before merge.

## Approach

Reuse BLUM's authoritative paper and Forex decision engines. Add a prospective registration ledger and a read-only Alpha Desk to the existing Alpha page. A Bloomberg-scale data terminal needs licensed datasets and infrastructure; weight training requires valid datasets and a budget. Neither substitutes for a prospective, cost-aware track record. This release concentrates on that track record and fixes known read-model errors.

## Registration and provenance

One additive SQL table records source identity, market, actual registration time, source decision time, the frozen decision manifest and its SHA256. The paper candidate creator and Forex orchestrator register new decisions within their existing transactions. Rejected and unfilled calls remain visible. Registration is idempotent and refuses changes to an existing manifest. Historical rows are never retrospectively registered as prospective evidence. A source row missing a registration remains legacy evidence.

Price provenance must identify a provider, market timestamp and availability timestamp. All timestamps must be at or before the decision. Equity daily data older than 96 hours and Forex quotes older than 180 seconds are unavailable for active calls. A Forex quote needs positive finite bid/ask, ask >= bid and named source; timeframe acquisition dates must not exceed the decision. Missing provenance, invalid side/geometry, non-finite values and source mutations block qualification. Confidence is an explicitly labelled heuristic, not a calibrated probability.

## Evidence and ranking

The Desk reads at most 2,000 registered calls, reports its window, and keeps equities and Forex separate. A closed call counts as qualified forward evidence only if registration preceded closure, input integrity remains intact, timestamps are causal, fill/accounting are valid and net P/L reconciles with explicit execution costs. Benchmark-relative percentage returns additionally require positive account-currency notional and gross-return/notional reconciliation. Missing benchmarks remain missing. Unfilled and rejected calls never enter realized-performance samples.

Report observed P/L and R separately from qualified paired alpha. Do not annualize irregular per-trade returns or treat average trade excursion as portfolio drawdown. Cluster paired excess returns by closure date for a deterministic 95% bootstrap interval. A positive-sample verdict requires at least 100 paired observations, 30 closure dates and three assets, with a lower confidence bound above zero. This is sample evidence, never a production-promotion or competitor-superiority certificate. All failures and exclusions are counted. Existing positive historical grades are marked uncertified when provenance is not independently validated.

Open eligible calls are shown with direction, frozen entry/stop/target, model, quote age, registration hash and source status. Rankings remain within each market and use stored expected net edge only; absent edge estimates are not invented. Prices are never fetched or financial decisions generated by page load.

## Integration and persistence

Expose a reviewed GET/HEAD `/api/alpha/desk` through the shared route policy and embed it in the existing Alpha snapshot. Keep mutations private and paper-only. Preserve existing source tables and additive migrations. Correct Alpha's newest-500 sampling to include a separate bounded query for older closed trades, deduplicate source identities and avoid counting the same live-forward row twice.

Embedded PostgreSQL still uses periodic backups and cannot guarantee zero-loss restart durability. Make restore failures terminate startup rather than continue into a partially restored or empty database. Expose the actual durability mode in the Desk; do not claim this fixes recovery-point loss. Strict durability requires external PostgreSQL. No new paid infrastructure, GPU training or broker execution is enabled.

## Verification and release

Use real SQLite integration tests for registration, immutability, causal/stale inputs, net-cost reconciliation, unfilled outcomes, separate markets, read-only access and older closed trades. Test bootstrap evidence with hand-derived groups and insufficient samples. Test failed restore via executable shell fixtures. Run the full backend suite, frontend tests/build and gateway tests/types. Review, merge only after required CI passes, wait for exact-revision HF and Cloudflare readiness, smoke-test the Desk and five product surfaces, and publish BLUM 2.3.0 with reproducible reports and explicit limitations.
