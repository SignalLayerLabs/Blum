# Independent review — 26 October 2026

Status: corrections implemented; final CI checks pending. Each of the ten confirmed findings was reproduced in `tests_v3/test_review_findings.py` before correction. All ten tests now pass locally, alongside the full v3 suite (71 passed, two PostgreSQL cases awaiting CI).

Important findings:
1. Order retries regenerate decision clocks before idempotency comparison; strategy recovery has the same risk.
2. Manual paper orders are not visited by the subscription-only cycle.
3. Symbol-only position/source identity can merge incompatible currency contracts.
4. New-risk settlement does not recheck account halt, loss stops and stale marks completely.
5. Several orders can each consume the full capacity of one observation.
6. Ordinary partially filled stops do not retain activation.
7. Paper stepping omits configured financing that replay applies.
8. Caller-supplied future provenance can admit future observations; availability ordering needs validation.
9. Provenance-only changes can bypass consumed confirmation protection.
10. Stored family trial counts and multiplicity intervals become stale after more alternatives are registered.

Additional findings at review time: charts should expose missing valuation segments; the web dependency lockfile was absent; PostgreSQL concurrency checks needed independent repositories rather than one process-local lock.

Corrections: API/strategy requests replay the original command identity before resolving clocks/data again; manual orders are included in cycles; incompatible contracts are rejected; settlement rechecks full new-risk status/loss/freshness; shared capacity is committed atomically with fills; STOP activation is durable; paper financing is accrued once per held interval; intake uses the acceptance clock and causal availability; confirmation consumption follows economic instrument/time intervals; registration updates trial counts and invalidates stale inference.

The chart now splits missing observations into separate segments (client regression test); the dependency lock generated by the successful CI web build is committed; PostgreSQL concurrency tests use independent repository/connection pools.
